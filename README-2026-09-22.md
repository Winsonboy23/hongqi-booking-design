## 兩版簡約提案

A 與 B 的資料和互動都跟原稿 `Main.dc.html` 相同（地區 → 館別 → 點日期展開當天課程），只換視覺語言。兩張都拿掉了粗描邊、貼紙陰影、圓體字、粉色按鈕與手寫英文。

A・清爽：白底、1px 細線、8px 圓角、無陰影，思源黑體，品牌深藍為唯一主色，課程改成分隔線列表。Tweaks 可切主色：深藍 `#2f4a6d`、墨綠 `#1f5f4a`、炭灰 `#2b2f36`。

B・運動：深藍黑頂部區塊，日期、時間、價格用 Barlow Condensed 窄體粗字，格線式日曆，萊姆綠強調色。Tweaks 可切強調色：萊姆綠 `#d4f24a`、薄荷綠 `#7ee0b0`、羽球黃 `#ffd84d`。

這兩版刻意沒有跟隨「弘淇羽球設計系統」（那套 token 是可愛風）。客戶定案後，設計系統要出新版本，其餘 14 張畫板也要跟著換。

## 系統流程圖

泳道式：五個角色（學員、前台網站、金流商、後台管理員、會計）× 七個階段（事前設定、選課、結帳、付款、付款結果、完成・查詢、開票・對帳）。實線是操作流程，虛線是資料同步。深藍框的方塊在畫布 Play 模式下點了會跳到對應畫板。

圖上標「待確認」的三件事要跟客戶定案：

1. 金流回傳付款成功後，要自動改成「已付款」，還是照規格全部手動改？
2. 名額在付款成功才扣，還是建立訂單時就先保留？
3. 一直沒付款的「待付款」訂單，要不要逾時自動取消並釋出名額？時限多久？
